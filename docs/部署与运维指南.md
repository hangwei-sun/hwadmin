# HwAdmin 多环境部署与运维指南

> **核心理念**：让你的 AI 智能体读懂并快速创造应用。  
> 无论你是把源码直接交给 **AI 编码智能体（Antigravity / Cursor / Claude Code / Windsurf）** 一键开发，还是将发布包上线到生产服务器，请先根据你的运行条件选择最匹配的部署方式。

> 1.6.8 执行范围与统一分发策略：
> - **唯一统一发行包 (`hwadmin-v1.6.8.zip`)**：同时内置完整源码仓（AI Agent 二开 + `./hw start`）、已编译 `server/public/admin/` 与生产依赖 `server/vendor/`，兼顾本地开发与宝塔/Docker 生产直跑。
> - **部署执行器支持范围**：**首发自动生产执行器为 Docker 单机**（`python3 scripts/hw-deploy.py apply --target=docker`，支持 MySQL 8.0+ / PostgreSQL 16+ 隔离编排、随机 0600 初始凭证、生产健康探针与双库/附件一致性恢复）；`--target=local` 仅用于本地 SQLite 目录验收；**宝塔（`--target=baota-nginx`）当前提供只读部署计划（`hw deploy plan --target=baota-nginx`）与下方手动/半自动部署步骤**，不自动远程覆写生产服务器（`apply --target=baota-nginx` 将明确拒绝并输出手动步骤）。外部服务器、域名/HTTPS 证书与容器镜像拉取仍需目标环境实际验收。

## 从本地预览到一键构建上线（最短实操闭环）

1. **本地开发与预览**：执行 `./hw start website`（或 `admin` / `miniapp`），自动初始化 SQLite 示例数据并启动预览服务；默认后台账号 `admin / Admin12345`。
2. **构建同步静态产物**：页面与业务确认后，将管理端与官网前端构建同步到后端 `server/public/`：
   ```bash
   pnpm --dir admin-ui check && pnpm --dir admin-ui build:sync
   ./hw verify
   ```
3. **打包与上线交付**：
   - **宝塔面板（推荐生产首选）**：将统一包解压至站点根目录并把运行目录设为 `/server/public`，先将 `server/public/nginx.htaccess` 写入宝塔「伪静态」，再直接访问 `/install/` 完成安装与安全校验；也可运行 `./hw deploy plan --target=baota-nginx` 查看配置计划。
   - **Docker 单机（自动化容器执行）**：`./hw deploy apply --target=docker --artifact=release/hwadmin-v1.6.8.zip --db-driver=mysql`（或使用仓库根目录 `docker compose up -d --build`）。
   - 生成统一完整包：`./hw package`（默认输出 `release/hwadmin-v1.6.8.zip`）。

## 二、包内目录说明（发布包 vs 源码仓）

- **GitHub 源码仓**：
  - `server/`：ThinkPHP 8.1 后端源码（`core/` 框架内核 + `app/` 业务应用 + `plugins/` 插件 + `database/` 迁移）
  - `admin-ui/`：管理后台 Vue 3 + Vite + TypeScript + Pinia 源码，`admin-ui/mobile/` 为 uni-app + Wot UI V2 通用移动端源码
  - `scripts/`：WSL 开发、双端联调与打包运维脚本
  - `docs/`：全部架构规范、接口契约与本指南
- **统一完整发行包（`hwadmin-v1.6.8.zip`，唯一官方包）**：
  - 完整保留源码仓布局、跨平台入口（`hw` / `hw.ps1` / `hw.cmd`）、运行时矩阵与准备器（`scripts/hw-runtime.py`）、三套业务模板（`templates/`）、完整 PHPUnit/Python 测试与 `docker-compose*.yml` 编排资源，并同步预置已编译前端 `server/public/admin/` 与生产依赖 `server/vendor/`，供 AI 智能体解压即开工或直接上线部署（运行目录设为 `/server/public`）。
  - **`artifact-manifest.json`** 与外部 `.sha256` 记录包内所有文件的 SHA-256 校验值；不包含 `.env`、安装锁、本地测试库与研发临时文件。

## 三、方案 A：宝塔面板生产环境部署（推荐生产首选）

> **边界说明**：宝塔路径当前提供只读部署计划（`python3 scripts/hw-deploy.py plan --target=baota-nginx`）与下方标准化引导；安装向导支持通过本机回环宝塔 API 或一键终端命令自动备份写入伪静态，不自动远程覆写外部生产服务器。

宝塔面板环境无需在服务器上安装 Node.js 或 Composer，配合内置的**「部署安全检查向导」**即可完成规则生成、自动/一键写入与实测校验（检查项与边界见本节第 5 小节）。

### 1. 服务器环境准备
- **PHP**：安装 **PHP 8.2 / 8.3 / 8.4**（推荐 8.4 LTS）。
- **必须扩展**：`fileinfo`、`pdo_mysql`（用 PostgreSQL 则开 `pdo_pgsql`）、`curl`、`mbstring`、`json`、`openssl`；建议开启 `opcache` 与 `redis`。
- **禁用函数**：若需在命令行执行 `think` 运维脚本，请在对应 PHP 的“禁用函数”中移除 `putenv`、`proc_open`（或仅在 CLI 下使用）。
- **数据库**：MySQL 8.0+ 或 PostgreSQL 16+，提前创建站点专用空库及独立数据库账号。

### 2. 上传代码与站点目录设置
1. 新建网站，将**统一完整发行包 (`hwadmin-vX.Y.Z.zip`)** 解压到站点根目录（例如 `/www/wwwroot/your-domain.com`），内置后端位于 `server/`。
2. 在「网站设置 → 网站目录」中：
   - **运行目录**：**必须设置为 `/server/public`**（兼容旧精简部署包为 `/public`），并点击保存。
   - 防跨站攻击（`open_basedir`）：确保允许访问站点根目录下的 `server/vendor/`、`server/app/`、`server/core/` 与 `server/runtime/`。
3. 目录权限：确保 `server/runtime/`、`server/config/`、`server/public/uploads/`、`server/public/plugins/` 对 PHP-FPM 运行用户（通常为 `www:www`）具备可写权限。

### 3. 先配伪静态，再访问 `/install/` 安装并核验（推荐）
1. 部署 SSL/HTTPS 证书（生产环境强烈建议全站强制 HTTPS）。
2. **先手动添加伪静态（只需改这一处）**：打开 `server/public/nginx.htaccess`，复制全部内容粘贴至宝塔「网站 → 设置 → 伪静态」并保存。
   - 规则已整合 `$hw_block_php` PHP 入口限制，在进入宝塔默认 `include enable-php-xx.conf;` 前即拒绝除 `/index.php` 以外的 `.php/.phtml/.phar`，**无需再前往“配置文件”手动修改 PHP 解析片段**，切勿在伪静态中保留两套 `location /`。
3. 直接访问 **`https://你的域名/install/`** 打开安装向导（若跳过第 2 步尚未设置伪静态，也可先访问兼容入口 `https://你的域名/index.php?s=/install/index/index`）。
4. **获取安装令牌**：首次访问安装页会在 `server/config/install.token` 生成一次性安全令牌，打开复制填入向导完成校验。
5. **一键验证与自动配置兜底**：在向导“宝塔配置与部署安全检查”中点击 **「实际检查」** 确认绿灯即可（若第 2 步未配伪静态，可在向导中直接复制单块伪静态、填写本机宝塔 API 密钥点按钮自动写入并重载 Nginx，或复制一键终端命令执行），随后填写数据库与管理员信息完成安装。
6. 安装完成后可通过后台 **「系统配置 → 部署安全复查」** 随时复检安全配置。

### 4. 手动 Nginx 伪静态参考（完整模板以 `server/public/nginx.htaccess` 为准）
```nginx
# 仅允许 /index.php 入口执行 PHP（在宝塔 enable-php 前直接拦截其余 .php/.phtml/.phar）
set $hw_block_php "";
if ($uri ~* "\.(php[0-9]*|phtml|phar)(/|$)") {
    set $hw_block_php "1";
}
if ($uri = "/index.php") {
    set $hw_block_php "";
}
if ($hw_block_php = "1") {
    return 404;
}

# 禁止访问内部代码与运行时目录
location ~* (runtime|application)/ {
    return 403;
}

# 禁止 uploads / plugins 静态目录执行 PHP 及脚本文件（^~ 避免被宝塔正则抢先匹配）
location ^~ /uploads/ {
    location ~* \.(php[0-9]*|phtml|phar|sh|cgi|pl|py|asp|aspx|jsp|html?|svg)(/|$) { return 404; }
    add_header X-Content-Type-Options nosniff always;
    try_files $uri =404;
}
location ^~ /plugins/ {
    location ~* \.(php[0-9]*|phtml|phar|sh|cgi|pl|py|asp|aspx|jsp)(/|$) { return 404; }
    add_header X-Content-Type-Options nosniff always;
    try_files $uri =404;
}

# 后台地址经 PHP 校验 admin_entry，并下发管理端安全响应头
location = /admin { rewrite ^(.*)$ /index.php?s=/admin last; }
location = /admin/ { rewrite ^(.*)$ /index.php?s=/admin last; }
location = /admin/index.html { rewrite ^(.*)$ /index.php?s=/admin last; }
# 更多安全响应头、/api/ /adminapi/ 前缀保护与 location / 完整内容请直接复制 server/public/nginx.htaccess
```
> 修改后务必执行 `nginx -t && nginx -s reload`（或在宝塔面板重载 Nginx）。若使用了自定义后台安全入口 `admin_entry`（例如 `my_panel`），建议同步更新或放行对应 SPA 路径回退规则（详见安装向导生成内容）。

### 5. 安装后的安全复查与检查项说明

- **后台随时复查**：超级管理员登录后台，进入 **「系统配置 → 部署安全复查」**，可重新生成配置或运行检查（无需删除安装锁，也不会重新安装数据库；普通管理员不可操作）。
- **临时凭据机制**：安装完成页提供的检查凭据仅 30 分钟有效并保存在当前页面内存中（不会写入 URL 或浏览器持久存储）；刷新或过期后请从后台入口进入复查。一次性 `install.token` 在安装完成后自动清除。

| 检查项目 | 通过条件 |
| :--- | :--- |
| 站点目录与静态通路 | `public/`、`uploads/`、`plugins/` 三处临时静态标记均原样返回 |
| PHP 入口限制 | 真实存在的根目录 `.php` 探针被拒绝（HTTP 403/404） |
| 上传与插件目录保护 | 真实存在的上传目录 `.php` / `.phtml` 及插件目录 `.php` 探针被拒绝（HTTP 403/404） |
| 伪静态接口路由 | 无 `index.php` 的诊断接口地址返回本轮随机挑战值 |
| 后台静态页面 | 后台入口 HTML 可正常读取 |
| HTTPS 访问 | 当前浏览器通过 HTTPS 访问；HTTP 内网调试仍会明确标记未通过 |
| 安装锁（安装后） | 安装检测接口返回预期的已安装锁定拒绝响应 |

> **安全边界与探针机制**：静态标记不可读、网络失败、重定向或响应不符均不会判通过（单纯访问不存在的 `probe.php` 得 404 不算禁执行有效）。检查所建临时脚本仅输出随机固定标记、不可预测并在检查结束时立即清理（异常中断会在下次检查按 5 分钟有效期清理）；浏览器探针只请求当前站点同源，宝塔 API 自动写入仅限显式传入本机回环面板地址（`127.0.0.1` / `localhost`）且密钥仅当次内存签名使用、不落盘。自定义反向代理、证书续期、数据库端口、备份恢复及业务权限仍需单独验收。

## 四、方案 B：Docker Compose 一键编排（容器化与多实例部署）

仓库已提供多栈编排文件 [`docker/php/Dockerfile`](../docker/php/Dockerfile)、[`docker-compose.yml`](../docker-compose.yml) 与环境变量模板 [`.env.docker.example`](../.env.docker.example)。

### 1. 配置环境变量
```bash
cp .env.docker.example .env
```
编辑 `.env`，**务必修改所有默认强口令**（`REDIS_PASSWORD`、`DB_PASS`、`DB_ROOT_PASSWORD`）：
- 默认使用 **MySQL 8.0**（`COMPOSE_PROFILES=mysql`、`DB_DRIVER=mysql`）。
- 如需切换 **PostgreSQL 16**，修改为 `COMPOSE_PROFILES=pgsql`，并将模板底部的 `DB_DRIVER=pgsql` 与对应端口/主机注释取消即可。

### 2. 启动全栈服务
```bash
docker compose up -d --build
```
默认对外暴露端口为 `HTTP_PORT=8080`：
- 安装向导：`http://127.0.0.1:8080/install/`
- 门户首页：`http://127.0.0.1:8080/`
- 管理后台：`http://127.0.0.1:8080/admin/`

### 3. 容器内执行常用 CLI
```bash
docker compose exec hwadmin-php php think hw:inspect --json
docker compose exec hwadmin-php php think hw:test
```

## 五、方案 C：WSL + SQLite 零配置开发（AI 智能体与 Windows 本地开发首选）

Windows 用户无需在宿主机折腾 PHP、MySQL 与伪静态服务，直接在 WSL Ubuntu 中使用内置脚手架即可实现 **10 秒启动全栈开发与自动化验收**。

### 1. 初始化环境与免配置 SQLite 数据库
```bash
# 1. 环境体检（检查 PHP / Composer / SQLite 扩展）
bash scripts/wsl-dev.sh doctor

# 2. 一键初始化 SQLite 数据库、执行全部迁移与创建超级管理员
bash scripts/wsl-dev.sh install-sqlite

# 3. 验证系统语法与全量冒烟测试（统一包若缺 phpunit 可先执行 ./hw bootstrap --with-test）
bash scripts/wsl-dev.sh lint
bash scripts/wsl-dev.sh test
bash scripts/wsl-dev.sh smoke
```
> **Windows / WSL 跨文件系统提示**：如需将仓库目录复制到 WSL 临时目录做隔离验证，严禁整包 `cp -r`（会把超大依赖与 Rust 编译缓存拖慢跨盘 I/O），请使用 `rsync -a --exclude=node_modules --exclude=src-tauri/target --exclude=.hw-state` 或直接交由 `scripts/wsl-dev.sh serve-fast` 自动同步。
默认超管账号：`admin` / `Admin12345`（仅限本地敏捷开发使用，上线前务必修改或重新通过安装向导初始化）。

### 2. 双端联调与代码打包同步
```bash
# 一键同时拉起后端 PHP 内置服务 (:8000) 与 PC 管理端 Vite 热更新 (:15173)
bash scripts/dev.sh
# Windows PowerShell 也支持：
pwsh scripts/dev.ps1
```
若仅开发后端：
```bash
bash scripts/wsl-dev.sh serve   # 监听 0.0.0.0:8000
```
前端改动完成准备打包并同步到后端 `server/public/admin/` 静态目录时，在 `admin-ui/` 目录执行：
```bash
pnpm check        # 一键运行 vue-tsc + oxlint + node --test 核心单测 + 生产构建
pnpm build:sync   # 构建并将 dist 产物原子同步到 ../server/public/admin/
```
通用移动端开发位于 `admin-ui/mobile/`，详情参阅 [`移动端接入指南`](移动端接入指南.md)；Windows 桌面客户端（Tauri 2）位于 `admin-ui/src-tauri/`，详情参阅 [`桌面端接入指南`](桌面端接入指南.md)。

## 六、方案 D：原生 Linux (Nginx + PHP-FPM) 部署要点

适合使用 Ubuntu / Debian / Rocky Linux 直接通过系统包管理器或 CI/CD 流水线部署：
1. 参考 `docker/nginx/default.conf` 与 `public/nginx-baota.conf.example` 配置 server 块，确保 `root` 指向站点 `public/` 目录，且仅 `location = /index.php` 转发至 `fastcgi_pass`，拒绝一切直接访问或执行 `public/uploads/`、`public/plugins/` 下的脚本文件。
2. 在发布包根目录（或 `server/`）也可直接通过 CLI 执行免 Web 安装（适合自动化流水线）：
   ```bash
   cp .example.env .env
   # 修改 .env 中的数据库连接参数与 APP_DEBUG=false
   php think hw:install
   ```
3. 生产环境切勿设置 `APP_DEBUG=true`，且安装完成后确认 `config/install.lock` 已生成、`config/install.token` 已清理。

## 八、常见部署故障排查 (FAQ)

- **Q1：首页能打开，但访问 `/install/`、`/adminapi/...` 返回 Nginx 404，而 `/index.php?s=/install/` 正常？**  
  **答**：Nginx 伪静态未生效或未加到正确的 server 块。请确认已在对应站点生效完整 Rewrite 规则，并执行 `nginx -t && nginx -s reload`。Nginx 不会自动读取目录下的 `.htaccess` 或 `nginx.htaccess`。
- **Q2：访问后台 `/admin/` 刷新子页面报 404？**  
  **答**：缺少 `location /admin/ { try_files $uri $uri/ /admin/index.html; }` SPA 回退规则，或站点的通用静态资源正则 `location ~ .*\.(js|css)$` 劫持了路径，请按安装向导推荐配置合并规则。
- **Q3：验证码不显示或安装提示缺少扩展？**  
  **答**：HwAdmin 验证码为纯矢量 SVG，无需 GD 扩展；但文件 MIME 真实校验与后端接口依赖 `fileinfo`、`pdo_mysql`/`pdo_pgsql`、`mbstring`、`curl`、`openssl`，请在 PHP 配置中启用并重启 PHP-FPM。
- **Q4：数据库迁移 / 命令行报 `open_basedir` 或权限错误？**  
  **答**：检查 PHP-FPM `open_basedir` 设置是否覆盖了 `vendor/`、`core/`、`runtime/`，以及 `runtime/`、`public/uploads/`、`public/plugins/` 目录属主是否为运行用户（如 `www` / `www-data`）。
