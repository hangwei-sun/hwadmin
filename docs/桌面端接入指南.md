# Windows 桌面端接入指南

HwAdmin 的 Windows 客户端使用 Tauri 2，直接复用 `admin-ui/src/`、`library/` 的 Vue 3 页面、Element Plus、HwAdmin 主题、菜单及管理员权限逻辑。移动端仍是独立的 `admin-ui/mobile/`（uni-app + Wot UI V2），不替换移动端工具链，也不复制一套管理后台源码。

## 工程边界

- `admin-ui/src-tauri/`：Rust 入口、原生窗口、权限、图标及 Windows 安装包配置。
- `admin-ui/src/utils/platform.ts`：平台判断、服务端 URL 与系统浏览器适配。
- `admin-ui/.env.desktop.example`：每个具体项目的服务端配置模板。
- `admin-ui/dist-desktop/`：桌面专用前端产物；与 Web `dist/`、移动端 `mobile/dist/` 隔离，不提交 Git。
- `admin-ui/src-tauri/target/`：Rust 构建缓存、可执行文件与安装包，不进入 Git 或框架源码发布包；`Cargo.lock` 应提交以锁定依赖。

桌面包内置前端，通过网络调用现有 `/adminapi` 和 `/api`；本次没有把 PHP、数据库或 WSL 装入客户端，也不提供离线数据库同步。桌面窗口默认 1440×960，最小 1024×720，保留 Windows 原生标题栏与窗口操作。

## 开发环境

在 Windows 安装 Node.js 22.18+、pnpm 10、Rust MSVC 稳定工具链、Visual Studio C++ Build Tools（“使用 C++ 的桌面开发”及 Windows SDK）、Microsoft Edge WebView2。安装器默认采用 NSIS；MSI 需要另行配置 WiX 及其环境要求。

```powershell
cd admin-ui
pnpm install --frozen-lockfile
Copy-Item .env.desktop.example .env.desktop.local
pnpm desktop:dev
```

桌面开发固定使用 `http://127.0.0.1:15174`，端口被占用时直接报错，避免误连其他开发服务；前端不会自动打开浏览器。先用现有 HwAdmin 工具链单独启动后端，桌面默认连接 `http://127.0.0.1:8000`。也可以用 `pnpm desktop:dev:web` 只启动桌面配置的 Vite 服务以调试界面。

## 服务端地址与跨域

`.env.desktop.local` 示例：

```dotenv
VITE_DESKTOP_SERVER_ORIGIN=https://your-hwadmin.example.com
```

填源地址，不带 `/adminapi`、子目录、账号密码、查询参数或锚点。生产只接受 HTTPS，本机 loopback 可用 HTTP。配置在构建时写入前端，变更后需要重新构建；这里只放公开服务地址，不放密钥。模板默认地址用于本机开发，不代表线上服务已经部署。

桌面静态页面与后端属于不同源，需要在**对应后端**现有 `.env` 中配置精确的来源白名单：

```dotenv
HW_CORS_ORIGINS=https://tauri.localhost,http://127.0.0.1:15174
```

保留已有白名单并追加需要的来源；生产只需保留 `https://tauri.localhost`，开发端口按需启用。后端已有 CORS 中间件支持 `Authorization`、`Content-Type` 和 `X-Token`，不需要改鉴权协议或放开通配来源。Web 版仍使用原有同源代理。桌面版仅向配置服务端的 API 路径注入管理员凭据，外部资源不携带管理员 Token。

默认 CSP 允许 HTTPS 后端与本机 `127.0.0.1:8000`，其他本机端口需同步调整 `tauri.conf.json` 的 CSP。后端返回的上传 URL、验证码图片、预览地址须可从客户端访问；自有图片不能依赖服务器内网地址。配置图片、头像、编辑器上传、商城和公共业务预览链接已适配服务端源地址。

## 构建与验证

```powershell
cd admin-ui
pnpm check                  # 既有 Web 类型、核心测试与生产构建
pnpm desktop:check          # 类型、桌面契约测试、桌面前端构建、Rust 检查
pnpm desktop:build          # Windows NSIS 安装包
pnpm desktop:build --no-bundle # 只构建可执行文件
```

NSIS 安装包输出到 `admin-ui/src-tauri/target/release/bundle/nsis/`。安装时按需下载 WebView2，完全离线分发时改为 Tauri 官方的离线 WebView2 安装模式并评估安装包大小。Windows CI 会构建桌面前端、Rust 可执行文件并运行类型及契约检查，不自动发布。

桌面构建不注册 PWA Service Worker，强制使用 Hash 路由，以支持安装后深层页面导航和刷新。Web 的构建及同步仍使用 `pnpm build:sync`，不会把桌面产物同步到 PHP 公共目录。

现有 PWA 更新组件的虚拟模块在桌面模式映射到空适配，避免缺失模块导致启动停留在加载页；Web 继续使用真实 PWA 插件。部署安全复查依赖同源网页，桌面端引导在浏览器中执行。

## 具体项目定制与能力预留

具体项目修改 `src-tauri/tauri.conf.json` 的 `productName`、唯一 `identifier`、窗口标题和 `icons/` 图标；Tauri 安装版本直接读取 `admin-ui/package.json`，Rust 包版本随框架发布同步。现有 `hwadmin.config.js` 继续管理页面品牌配置，布局和主题仍由 HwAdmin 维护。

系统浏览器通过官方 opener 插件打开 HTTP(S) 链接；当前没有启用任意 Shell 执行、文件读写、自动更新、托盘或本地数据库权限。需要这些能力时，在具体项目引入对应插件并按窗口配置权限。代码签名证书、更新地址及签名密钥由项目发布阶段配置，通用框架不内置。

Vue 源码插件页面直接复用。远程 HTML 微视图除了 CORS，还受服务端 `X-Frame-Options` / CSP `frame-ancestors` 限制，不能因桌面打包就保证可嵌入；涉及 `parent` 同源访问的旧插件也需要改用显式通信协议并专项验证。公共预览可用系统浏览器打开，不能通过移除服务端防护来宣称兼容。

Wot UI V2 属于 uni-app 组件库，不直接混入普通 Vue 管理后台。本次 Windows 版复用 HwAdmin PC 界面；未来学习客户端若需要复用 Wot 页面，可另行把 `mobile/` 的 H5 产物接入桌面壳，并适配宽屏、键鼠和平台专属 API。
